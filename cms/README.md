# Al-Qawsan Scientific Bureau website and dashboard

A Laravel app that serves the bilingual (English / Arabic, RTL) website for
alqawsangroup.com and the dashboard used to edit it. The site follows the Al-Qawsan design
system and the structure in `proposals/alqawsan-website-proposal.pdf`.

- **Website** at `/`: one page; `public/site.js` renders every section from the content the
  server embeds as `window.QS`.
- **Dashboard** at `/admin`: sign in to edit every page, text, photo, list and setting, and
  to read what visitors send through the forms.

## Run it locally

Needs PHP 8.3+ with `pdo_sqlite` (or MySQL), and Composer.

```sh
cd cms
composer install
cp .env.example .env && php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed                  # loads the launch content
php artisan admin:user you@example.com      # prints a password
php artisan serve                           # http://localhost:8000 and /admin
```

If the page stays blank, check the terminal running `php artisan serve` and
`storage/logs/laravel.log`. The usual causes are: `php -v` below 8.3, `composer install`
not run (no `vendor/` folder), no `.env` or app key, or `migrate` not run (the site keeps
sessions in the database). Open the address `php artisan serve` prints, including
`:8000`.

`php artisan db:seed --class=SiteContentSeeder` puts the launch content back. It
replaces what was edited in the dashboard, so don't run it on a live site. Form messages,
photos and users stay.

## What the dashboard edits

| Area | Where it shows |
|---|---|
| **Pages** (30) | Banner title, introduction, photo and icon; the page's sections, which you can add, reorder and edit (text, checklists, cards, steps, timeline, facts, photos, notes, forms, and automatic sections such as the map or the product table); menu section, order, related pages |
| **Interface text** (≈170) | Every button, label, heading, form field and message outside page content, in both languages, grouped and searchable |
| **Photos and files** | Upload (drag and drop) and reuse photos and PDF leaflets. Every photo field also has **Upload** and **Choose from library** |
| Home slides, Key figures, Service cards | Home page hero, figure cards, service cards and the footer services list |
| Products, Therapeutic areas, Partners | Product table and product pages (`#product-<id>`), filters, partner tiles by region with logos |
| News, Events, Gallery | Articles with their own pages (newest three on the home page), events list, photo gallery |
| Leadership, Group companies, Hubs, Open positions | People with photos, group companies with logos, hub addresses and phones, vacancies |
| Menu sections, Form routing, Settings, Users | Menu labels and order; which team answers each form and who gets the email alert; phone, email, logo, links, footer quick links; dashboard users |
| **Inbox** | Partnership, inquiry, medical information, job application (CV download) and newsletter messages; unread counts; export to Excel (CSV) |

Changes show on the site as soon as they are saved (the content cache clears on every save).

## Safety

- Text typed in the dashboard keeps only `<b>`, `<strong>`, `<em>`, `<br>` and
  `<bdi dir="ltr|rtl">` (for numbers and Latin names inside Arabic); everything else is
  escaped. Links must be `https://`, `mailto:`, `tel:`, `#page` or `/path`. Photo paths
  must point inside `public/uploads/` or `public/assets/`.
- Uploads: JPG, PNG, WebP, GIF and PDF up to 8 MB (no SVG).
- Forms: CSRF token, hidden honeypot field, 5 messages per minute per visitor, server-side
  validation. CVs (PDF or Word, up to 5 MB) are stored outside `public/` in
  `storage/app/private/submissions/` and only the dashboard can download them.
- Dashboard: session login, 5 attempts a minute, `noindex`. Create users with
  `php artisan admin:user` or under Users.
- Alert emails use Laravel mail (`MAIL_*` in `.env`). If no mailer is configured, messages
  are still kept in the inbox.

## Deploying

Point the web server at `cms/public`. Set `APP_ENV=production`, `APP_DEBUG=false`,
`APP_URL`, the database, and `MAIL_*`. Then run `php artisan migrate --force --seed` once,
create a user, and cache with `php artisan config:cache route:cache view:cache`.
`public/uploads/` and `storage/` must be writable and are not in git, so back them up with
the database.

`php artisan site:export <folder>` writes a static copy of the site with the current
content (`content.js` next to `index.html`). Use it for previews: forms in a static copy
only show their confirmation.

## Design decisions

- Colours, radii, spacing, shadows, focus treatment and component markup come from
  `public/design-system/` (`qs-btn`, `qs-card`, `qs-badge`, `qs-timeline`, `qs-field`,
  `qs-table`, HexPattern geometry). The dashboard uses the same tokens and components.
- Fonts, at the client's request: **Tajarib** for Arabic headings, **Alexandria** for
  English headings, **Cairo** for body text, set through the `--font-*` tokens in `site.css`.
- The map follows the brand rule: served governorates in `navy-800`, hubs as `orange-500`
  pins. The hub list comes from Hubs and branches.
- The logo is the client-supplied lockup and is never mirrored for Arabic. Replace it under
  Settings (a vector SVG from marketing would be sharper, but SVG uploads are blocked for
  safety, so use a large PNG).

## Tajarib font files (not in this repository)

Tajarib is by Harf Type / Harf Library (abdulmalik@harflibrary.com). Its licence is free
and allows commercial use on websites, but forbids making the font files available for
download, modifying them or converting them. This repository is public, so the files are
**not committed** (`cms/public/fonts/tajarib/` is in `.gitignore`).

To use them, copy these original files, unchanged, into `cms/public/fonts/tajarib/` on
the server:

- `Tajarib_Typeface_Medium.otf`
- `Tajarib_Typeface_Bold.otf`
- `Tajarib_Typeface_Black.otf`

Without them, Arabic headings fall back to Alexandria and everything else still works.
